
### 回测接入时踩的三个坑（后来者必读）

1. **窗口数据陷阱**：engine 门控判定必须用未裁剪全历史——63 日窗口
   < 65 根均线需求 → 全部 fail-open → 门控版与无门控版逐字节相同
   （症状：d_cycles 全 0）。判定'窗口内日期'，数据用全历史。
2. **continue 跳过循环尾**：拦买入时 `continue` 会连 equity 记录与不变式
   检查一起跳过 → 净值曲线缺被拦日 → final/identity_error 全错
   （589720 early 窗口 identity 差 200.8）。拦的只能是'动作'，不是'迭代'。
3. **顺延语义**：被拦买入顺延到次日（价格仍在 target 下方照样触发），
   trades 总数不必然减少。诚实断言是'被拦日零新格买入'，
   不是'总笔数减少'。合成夹具容易'被拦日无买入信号'——用实证受影响的
   真实形态（长横盘→阶梯深跌→修复）构造测试。

## 10-27 cron 静默失效事故（最重要的教训）

**现象**：09:20 推送照常含 589720 买入 G 格，⛔ 一条没有。前一晚开发环境
预演一切正常（拦截生效）。

**根因链（完整复现）**：
```
cron no_agent 环境 sys.path 只有仓库根目录（无 tools/）
  → fetch_daily_regime 函数内 import market_phase_check（顶层名，
    模块实际在 tools/ 下）抛 ImportError
  → 外层 except Exception 吞掉 → dict(adx=None) 且不带 bars
  → RegimeGate 拿不到任何数据 → fail-open 不拦
  → 连完全不依赖 tools/ 的五线判定都被跳过
```

**修复（5173a50）**：
1. `_load_market_phase_check()`：tools 子包 → tools 目录注入 path → 顶层兜底，
   三级定位。
2. `fetch_daily_regime`：**ADX 算不出时仍返回 bars**（五线判定只吃日线）
   ——组件失败只降级该组件，不能拖死其他不依赖它的判定。
3. 回归测试 `test_cron_env_gate.py`：**子进程模拟 cron 纯净 sys.path**，
   断言 has_bars=True 且 blocks=True。

**教训（必须内化）**：
- **生产验证必须在 cron 同构环境跑**：子进程里只注入 cron 实际有的
  sys.path，跑生产脚本本体（不是开发环境里的 import 组装）。'开发环境
  预演通过'不等于'生产生效'。
- **宽 except 是静默失效的温床**：`except Exception: return 默认值` 会把
  import 失败、网络失败、逻辑错误全部折叠成同一个 fail-open。降级必须
  分层：哪个组件失败就只降级哪个组件，并在 reason 里如实标注。
- fail-open 的方向性代价：门控 fail-open = 放行买入（用户多接货）；
  报警 fail-open = 漏报。设计时要明知哪个方向在失败时更安全。

## 10-28 cron 静默失效二次复发（真根因：解释器不匹配）

**现象**：5173a50 修复后的第一个交易⽇，09:20 cron 推送再次无 ⛔ 且含两只
五线全破 ETF 的买入建议。用户 09:23 报告。手动跑同一脚本同一数据——拦截正常。

同类事故（10-27/10-28）都是'验证环境≠生产环境'：第一天错在 sys.path，第二天
错在解释器。

**修复（fb49ea2）——解释器钉子**：

```python
if __name__ == '__main__' and not _IS_312:
    sys.exit(subprocess.call([SYSTEM_PY, os.path.abspath(__file__)] + sys.argv[1:]))
```

同款钉子铺到 hermes-home/scripts 全部 10 个 confirmed_runtime 系 cron 脚本
（confirm/eod/rollover/intraday/ops/preview/weekly_rotation/run_rotation/

**铁律（升级版）**：cron 验证 = 真实解释器 + 真实 sys.path + 生产脚本本体，
三者缺一不可。找到调度器实际用的 python（`AppData/Local/hermes/tools/python-*`）

```
_fetch_regime_klines 单次拉数、无重试
```

3. **实测**：模拟早间行情全挂，gate=缓存兜底，三只全部保持拦截；

5. **已知遗留（故意延后，二线加固）**：最终 fail-open 路径的 `⚠️ 行情缺失`

**10-29 实盘观察（数据源翻转）**：15:30 定时触发走东财主源拿到当日完整收盘K

save 前比较新旧 asof 取较新（未做，判定不变时无实际损失）。

### 775c4c2（10-29 下午）：缓存链路收尾三修——模拟推送验收一次抓出三个

**验收方法本身是本节的教训**：缓存架构落地后没有直接宣布完成，而是跑了
一次**全链路模拟推送**（cron 真实解释器 3.14 → launcher 接力 312 → 缓存
门控 → render），逐行读实际输出。一次模拟验收抓出三个真 bug：

1. **`_CachedGate.reason` 缺代码前缀**——⛔行渲染成"⛔ 收盘0.769低于…"
   没说是哪只 ETF。缓存路径的 reason 必须与 `RegimeGate._unified` 输出
   格式对齐（`"{code} {级别名}：{理由}"`）。渲染层 bug 只有看真实输出
   才能发现，测试断言 blocks_buy 不会暴露它。
2. **asof 语义错位**——盘中手动落缓存时 `fetch_daily_regime` 已 drop 今日
   未收K（数据=昨日收盘），但 `_regimes_to_cache` 把 asof 戳成
   `date.today()`。戳与数据不一致会让缓存新鲜度校验语义混乱。修法：
   **asof = bars 最后一根的实际日期**（盘中落=昨日、15:30 后落=今日），
   戳永远等于数据。
3. **部分失败丢保险（最重要）**——`grid_regime_cache.py` 某只拉不到时
   `save_regime_cache` 整体覆盖，把该标的的旧缓存条目一起丢掉——一次
   瞬时失败反而消灭了已有的保险。修法：**合并写回**——拉取失败的标的
   从旧缓存保留原条目（`warn: {code} 行情缺失，保留旧缓存条目`），
   宁可旧判定，不可无门控。验收当天 589720 真的连续两次拉取失败
   （行情源抖动，正是用户担心的场景），保留逻辑两轮都正确兜住——
   **用户担心的故障在验收时就真实上演，保险当场起效**。

**模拟推送验收铁律（新增）**：门控/渲染链路任何改动，交付前必须跑一次
全链路模拟（真实解释器 → 生产 launcher → render），逐行读输出对照预期
（⛔ 行数、买入行数、前缀完整性），而不是只跑单元测试。三个 bug 里
两个（前缀、覆盖丢保险）单元测试全绿也发现不了。

## ADX 滞后量化与「昨收口径」设计依据（10-28 用户两连问后的实测）

用户连续两问：「adx可以用于今天吗」「有人告诉我adx是滞后的」。两个都是对的，
但都要量化到设计里，不能停留在口头。

**滞后实测（13 次跌破60日线事件，逐日回放）**：

| 事件锚点 | 中位延迟 | 最坏 |
|---|---|---|
| 破60日线 → ADX≥20 | 2 天 | 31 天 |
| 破60日线 → ADX≥25 | 12 天 | 33 天 |

159363 自己就是活例子：2025-11-17 破位，15/18 天后 ADX 才到 20/25。
**结论：ADX 从不单独值班**——①级五线全破（价格位置，当天反应零滞后）当先锋，
②级 ADX 只在①够不着的急跌早期做确认票；阈值降到 20 本身就是给滞后让步。
滞后还有一个反直觉用处（全池 n=3684 已验证）：ADX≥25 组后续 10 日 +1.03%/胜率 57% ——
滞后使高 ADX 常出现在动能释放大半之后，所以它「确认趋势还剩多少」比「预测趋势开始」
更擅长。

**盘中掺入今日未收K的 A/B 实测（589720，10-28 16:14）**：

```
A 截至昨日收盘（生产口径）: ADX=18.5 +DI16.1 / -DI32.7 → 震荡
B 掺入今日盘中半根K（现价）: ADX=19.7 +DI15.2 / -DI31.5 → 仍震荡但逼近20
```

**为什么坚持昨收口径（拒绝盘中 ADX 进门控）**：
1. 半根K是噪音放大器——现价每分钟变，±DI 跟着抖，盘中 19.7 vs 昨收 18.5 的差异
   无法区分「真变了方向」和「盘中波动」；
2. 日内假信号：尾盘若拉回，盘中 ADX 可能掉回线下——拦截线附近会反复横跳，
   实盘决策不可逆而信号反复；
3. 回测不可复现：全池研究用完整收盘K，实盘掺半根K则实盘与回测行为不一致，
   回测验证意义打折。
日频网格决策（09:20 出建议、盘中只等触价）昨收口径滞后代价为零，换信号绝不抖动。
**未采纳的折中**（可提醒不拦截）：盘中实时 ADX 爬过 阈值−0.5 推一条
「⚠️逼近拦截线，收盘确认后明早生效」——挂在盘中触价监控里，行动仍等收盘。
