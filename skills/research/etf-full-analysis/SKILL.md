# ETF 全流程分析编排器（etf-full-analysis）

本 skill 是**编排层**，自身不做任何指标计算或评分。它只负责调度两个子 skill、复用数据、维护门控。

- 阶段一（粗筛）调用 `etf-analysis`：同类 ETF 比较 + 目标标的初步画像
- 阶段二（深研）调用 `etf-value-analyzer`：巴菲特三道闸门 + 六维评分
- 铁律：**不修改、不覆写两个子 skill 的评分逻辑与结论**；两者结论冲突时并列呈现，由用户裁决

## 流程

### Step 1 — 明确任务参数
向用户确认或从提问中提取：
- 目标 ETF 代码与市场（A股/港股/美股/QDII/商品）
- 用途：定投 / 核心仓 / 卫星仓 / 波段（影响阶段二权重解读，不改变计算）
- 是否指定同类比较集（未指定则由阶段一按跟踪同一/相近指数自动取同类）

### Step 2 — 阶段一：同类粗筛（etf-analysis 框架）
按 `etf-analysis` §3.1 的五步框架（规模→费率→跟踪误差→流动性→基金公司）对同类 ETF 打分排序：
1. 先用脚本取数（见 Step 4 数据规范），不要凭记忆填数
2. 输出同类排名表（规模、费率、年化跟踪误差、日均成交额、评分）
3. 给出目标标的在同类中的位置（第几名、是否触发剔除线，如规模<5亿）
4. 明确结论之一：`继续深研` / `同类存在明显更优替代品（列出）` / `工具品质不合格，建议终止`

**门控 G1**：若目标在同类中排名垫底且存在费率/跟踪误差显著更优的替代品 → 默认终止并推荐替代品，除非用户明确要求继续。

### Step 3 — 阶段二：深度评估（etf-value-analyzer 流程）
按 `etf-value-analyzer` 的强制顺序执行，**全部环节不可跳过**：
- Step 0.0 API 优先取数 → Step 0 多信源校验 → Step 0.5 近30天事件扫描 → Step 0.6 巴菲特三道闸门 → 六维评分 → 一票否决逐条检查（11项）→ Step 8 交卷自检
- 三道闸门任一不过 → 按 skill 原文判定"不推荐"并终止，不做六维评分
- 结论沿用其原文档次：强烈推荐 / 推荐 / 可关注 / 观望 / 不推荐 / 远离

### Step 4 — 数据规范（两个阶段共用，取一次）
- 取数引擎：优先 `@user_a8456463/etf-value-analyzer/scripts/fetch_etf_data.py`（yfinance+AkShare 双引擎）；同类比较所需的行情/规模/费率字段从同一批输出复用，避免重复请求
- 阶段一需要的 Tushare 模板仅作兜底参考，不要求执行
- 所有进入报告的数字必须来自脚本真实输出或双信源校验；取数失败的字段明确标注 `数据缺失`，禁止编造
- 已知环境问题：本机 yfinance 可能未安装、AkShare 实时接口可能被限流——取数失败时如实报告并询问，不得降级为"凭经验给结论"

### Step 5 — 合并报告
单一报告输出（保存到 `./reports/{代码}-ETF全流程分析-{YYYY-MM-DD}.md`），结构：
1. **同类比较表**（阶段一）+ 目标排名与 G1 门控结论
2. **三道闸门检查**（阶段二原文格式）
3. **六维评分摘要**（阶段二原文格式，含一票否决检查结果）
4. **合并结论**：
   - 两阶段一致 → 给出单一结论与操作建议（定投/配置/回避）
   - 两阶段冲突（如阶段一排名靠前但阶段二估值否决）→ 如实并列两条结论，标注冲突点，给"分批/等待"类中性建议，不强行合成
5. **信源与数据缺口披露**

## 边界
- 本 skill 不生成买卖时点建议，不做网格参数设计（那是 etf-grid-research / 回测引擎的职责）；用户要网格参数时提示改走对应 skill
- 子 skill 之间的任何指标阈值差异（如跟踪误差评级线）以 etf-value-analyzer 为准做深研判定，etf-analysis 的阈值仅用于阶段一排序
- 报告结尾标注：`编排器 etf-full-analysis v1.0 | 子skill: etf-analysis(be2c09f) + etf-value-analyzer(v2.1.0)`
