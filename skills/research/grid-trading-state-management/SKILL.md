# ETF 网格状态管理

用于 A 股 ETF 网格的操作单生成、部分成交记账、挂单去重和盘中连续穿格提醒。核心原则不是“每天固定一格”，而是维护一个与券商委托状态一致、可验证的网格状态机。

## 1. 网格状态机

每个网格 lot 至少包含：代码、lot ID、买入数量、实际成交价、卖出目标价、买入日期、可卖日期。操作单必须区分：

- **已成交持仓**：进入账本，可计算下一格和 T+1；
- **已挂未成交委托**：不能算持仓，也不能重复生成同一方向/价格/lot 的委托；
- **用户确认的部分成交**：只记确认的代码、方向、份额和实际成交均价；同票据其他动作保持 pending；
- **已撤/失败委托**：不改变持仓，允许重新规划。

挂单穿价不等于成交。只有券商成交明细或用户明确提供实际成交信息，才可以更新账本。

## 2. 卖出排序与 T+1

同一 ETF 有多个可卖 lot 时，卖出目标按价格从低到高排序，优先最近、最容易成交的一格；禁止用最高卖价的远端 lot 作为默认卖单。**卖出目标的选择只看 sell 价排序，不看 lot 本身的 T+1 状态**——当日买入的 lot 不能自己卖自己，但其卖价可以用更早的 T+1 库存来挂单。外层用 `available(pos, d)`（总 T+1 池）校验池是否覆盖数量即可。

若 C 格已经成交，正常状态应同时存在：C 格卖出目标和 D 格下一买入委托。不能因为当前价格尚未跌到 D 格，就延迟生成 D 格挂单；网格买单应提前挂在目标价等待成交。

## 3. 动态多格补仓

不要把“每天一格”当成永久策略规则。若实时价格在两个检查点之间连续跌穿多个网格，可同时生成多个下方限价单，但每格必须独立检查：

- 账户现金底线；
- 单标的成本上限；
- 已有 pending 委托；
- 当日已确认成交；
- 极端行情的最大预生成格数。

连续下跌不是自动成交证明，也不是无限补仓许可。每一格应有独立 lot ID 和可追溯订单记录；成交后下一层继续按实际成交价和现有持仓重算。

## 4. 15 分钟监控

盘中监控除检查单个 pending 限价是否被穿越，还要保存上一次价格并比较本次价格：

- 上次价 > 多个买入价 >= 本次价：发送一次“连续下穿 N 格”提醒，列出价格和数量；
- 上次价 < 多个卖出价 <= 本次价：发送一次“连续上穿 N 格”提醒，列出价格和数量；
- 提醒状态按交易日持久化，避免每 15 分钟重复轰炸；
- 提醒只要求用户核对券商成交，不自动记账、不把价格穿越当成交。

## 5. 每次重新生成操作单前的检查顺序

1. 读取当前账本和当日活动票据；
2. 查询实时价并确认报价时间戳属于当日连续竞价；
3. 清理已确认部分成交的动作，只保留未确认动作；
4. 检查旧委托是否仍挂着或已成交，避免重复撤挂/重复下单；
5. 对每个 ETF 先选最低目标价的可卖 lot；
6. 为已成交的最低 lot 生成卖单，同时保留下一格及所有已穿越格的买单；
7. 标出“建议委托”“已挂单”“已成交”三个不同状态；
8. 最终输出代码+中文名称、方向、数量、限价、T+1限制和需要用户核对的事项。

## 6. 回归测试要求

至少覆盖：

- 多个可卖 lot 时选择最低卖出目标；
- 当日买入 lot 不进入卖出候选；
- 已成交 C 格同时生成 C 卖单和 D 买单；
- 价格连续下穿多个买格时生成多个买动作，并受现金/成本上限约束；
- 票据部分成交只移除对应动作；
- 连续上穿/下穿提醒各自只发送一次；
- 报价未到连续竞价时间不得生成可执行价。
